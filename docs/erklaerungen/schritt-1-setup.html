Setup: vom leeren Ordner zur Live-Seite

Das Grundgerüst steht. Faden ist ein [[nextjs|Next.js]]-Projekt mit [[typescript|TypeScript]]. Der Code liegt auf [[github|GitHub]]. Jede Änderung geht über [[vercel|Vercel]] automatisch online.

01

Was jetzt funktioniert

Das Projekt läuft auf dem eigenen Rechner mit dem Befehl npm run dev. Vier Prüfungen kontrollieren den Code: [[lint|lint]], [[typecheck|typecheck]], [[test|test]] und [[build|build]]. Alle vier sind grün. Der Code liegt in einem öffentlichen [[repo|Repo]] auf GitHub. Vercel baut jede Änderung auf dem Hauptzweig und stellt sie unter einer öffentlichen Adresse online.

    05
    Entscheidungen und Alternativen
    
    
    
      
    Gewählt
    Projekt in einem Unterordner erzeugt
    Das Startprogramm [[cna|create-next-app]] bricht ab, wenn der Ordner nicht leer ist. So blieben CLAUDE.md und NOTIZEN.md unberührt.
    Alternative
    Die Dateien kurz wegräumen. Risiko: etwas vergessen zurückzulegen.
    
      
    Gewählt
    Node 24, an zwei Stellen festgelegt
    Eine Datei für den eigenen Rechner, ein Eintrag für Vercel. Beide nutzen dieselbe Version.
    Alternative
    Das vorhandene Node 23 behalten. Es ist aber keine [[lts|LTS-Version]] und weicht von Vercel ab.
    
      
    Gewählt
    Ein Ordner src/ für den App-Code
    Der App-Code liegt getrennt von Einstellungen, Datenbank und Doku.
    Alternative
    Alles im obersten Ordner. Ein Ordner weniger, aber unübersichtlicher.
    
      
    Gewählt
    Vercel mit GitHub verbunden
    Jeder Push auf main geht live. Jeder andere [[branch|Branch]] bekommt eine eigene Vorschau-Adresse.
    Alternative
    Von Hand veröffentlichen. Mehr Kontrolle, aber leicht zu vergessen.
    
      
    Gewählt
    [[shadcn|shadcn/ui]] erst in Schritt 5
    Die Einrichtung überschreibt die Farb-Datei. Das gehört zum Design-Schritt.
    Alternative
    Jetzt einrichten. Dann müssten wir die Farben in Schritt 5 ein zweites Mal anfassen.
    
      
    In Schritt 2 entschieden
    [[cache|cacheComponents]] ausschalten
    Die Vorlage schaltet es ein. Bei Seiten mit Login bringt es wenig und macht viel Arbeit.
    Alternative
    Anlassen. Dann braucht jede Seite mit Login zusätzlichen Code für Ladezustände.
    
    
    
  
    

  
  
    
    
    06
    Was schiefgehen kann
    
    
    
      
    Sicherheit
    Geheimer Schlüssel im Repo
    Eine .env.local mit echtem Schlüssel darf nie auf GitHub. Die [[gitignore|.gitignore]] verhindert das. Passiert es doch: den Schlüssel sofort beim Anbieter sperren. Nur löschen reicht nicht.
    
      
    Sicherheit
    NEXT_PUBLIC_ verwechselt
    Werte mit diesem Anfang landen im Browser. Ein [[apikey|geheimer Schlüssel]] darf ihn nie tragen.
    
      
    Pakete
    5 Warnungen bei npm audit
    [[audit|npm audit]] meldet Lücken, aber nur in ESLint. Das läuft nur beim Entwickeln, nicht auf der Live-Seite. Die automatische Reparatur hätte Next 16 kaputt gemacht.
    
      
    Umgebung
    Falsche Node-Version
    Ohne nvm use läuft vielleicht Node 23. [[npm|npm]] warnt dann, bricht aber nicht ab.
    
      
    Öffentlich
    Jeder Push ist sofort live
    Ein kaputter Stand auf main geht direkt online. Darum laufen vor jedem [[commit|Commit]] alle vier Prüfungen.
    
      
    Hinweis
    Neue Next.js-Version
    Next 16.4 weicht von älteren Anleitungen ab. Im Zweifel gilt die Doku, die mit Next.js mitkommt.
